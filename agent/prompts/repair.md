## 本轮要做的事

失败阶段：{{STAGE}}
错误类别：{{ERROR_CLASS}}

1. 先定位第一条 `ERROR:`；若只有 `multi-driven` / `multiple drivers` 警告，先修复多驱动。
   Vivado 可能在处理冲突驱动后仍返回综合完成，这并不说明电路结构正确。后续错误可能是连带结果。
2. 判断这是哪一类失败：
   - **接口不符** —— `interface mismatch`、`cannot find port`、`Module <X> not found`。
     照接口重写模块头，端口名一个字都不要改。这类失败得分为 0，优先处理。
   - **VRFC 10-1280：过程赋值目标不是变量** —— 找出日志指出的左值。ANSI 端口只写
     `output name` 时通常是 net，不能在 `always` 块中用 `=` 或 `<=` 给它赋值。若题目
     要求寄存输出，把端口声明为 `output reg name`（SystemVerilog 可用 `output logic name`），
     并在时钟块中直接、每个有效周期更新该输出；不要额外套一层未清零或多打一拍的寄存器。
     组合输出则保留 net，并改用连续赋值 `assign`。修复声明时保留题目规定的时序和重叠行为。
   - **语法错误** —— `VRFC 10-4982 syntax error`，多半是模块头缺分号、
     `begin`/`end` 不配对、位宽写法有误。
   - **位选越界** —— `VRFC 10-3705`、`select index ... out of bounds`、`index ... out of range`。
     检查被索引信号的声明和循环上下界。不要靠扩大对外接口掩盖错误；先确认该运算是否符合题意。
   - **不可综合的构造** —— `Synth 8-280`、`Synth 8-6156`。把 `real`、延时、
     文件 IO 之类去掉。
   - **意外的锁存器或多驱动** —— 组合逻辑分支没写全，或同一信号在两个 always
     块里被赋值。
3. **只改必要的部分。** 下方是磁盘中当前候选 RTL。保留已正确的算法、接口和结构，只修复能够解释本轮失败的部分；不要无依据地重写整个模块。
4. 若同一个错误连续两轮未解决，换一条思路，不要在同一处继续微调。
5. 如果当前诊断是综合失败，注意语法和接口已通过，避免把它们改坏；如果接口检查失败，先逐项对照接口，不要动算法。

优先只输出必要的局部修改，格式为单个 JSON 对象：
{"reason":"错误原因","edits":[{"search":"当前 RTL 中唯一匹配的原文","replace":"修正后的文字"}]}
每段 search 必须在当前源码中恰好出现一次；必要时包含相邻行。不要提供文件路径、命令或
Python 代码。程序会原子应用修改并重新检查，锚点错误会给出明确反馈，当前源码保持不变。
也接受完整修正后的单个 ```verilog 代码块。工具检查失败时不能返回 KEEP；不要附加测试台。
